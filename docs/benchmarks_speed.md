# Speed and Size Benchmarks

Back to [benchmarks.md](benchmarks.md). This file is generated by `bench/report.py` from `bench/results/results.csv`. Do not edit this file by hand. The plan behind this file is in [benchmark_proposal.md](benchmark_proposal.md). How the harness builds, runs and measures each program is in [bench_harness.md](bench_harness.md).

To make all of the numbers again:

```bash
python3 bench/run.py && python3 bench/report.py
```

## How to read the tables

- Each cell is **bytes / T-states**.
- Bytes: code and initialized data, minus the same compiler's empty program (the startup code and the library it always links). The BSS is not counted.
- T-states: Z80 clock cycles from `z88dk-ticks`, between the `TIMER_START` and `TIMER_STOP` labels of the program.
- † after the T-states: the count is for the whole run (start-up, printing and exit included), because the build has no TIMER labels. Do not compare such a count with the region counts of other compilers.
- A run counts only if its output matches the golden file in `bench/golden/`. **WRONG** means wrong output, **HANG** means no exit, **BUILD-FAIL** means the compiler, assembler or linker failed, and **BUILD-TIMEOUT** means a build tool hit its time limit (1800 s; 600 s for the hitech and dcc tools). (check) or (time) tells which build failed. **WRONG(time)**: the time build has the same defines as the check build, and its output is wrong. **HANG(region)**: the program did not get from `TIMER_START` to `TIMER_STOP`.
- Every compiler compiles the same source with the same defines. A program variant such as `sieve+static` adds a define for every compiler.
- Each compiler has a "size" mode and a "speed" mode. uc80 has one mode only.
